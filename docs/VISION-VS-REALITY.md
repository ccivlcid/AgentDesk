# AgentDesk — 비전 vs 현실 분석

> 우리 시스템이 추구하는 것과 현재 구현 상태의 Gap 분석

---

## 우리가 추구하는 것

### 한 줄 정의
> **AI 에이전트를 생성·실행·관찰·디버깅하는 통합 Agent Operating System**

### 핵심 비전
```
Create → Run → Observe → Debug → Optimize
이 전체 사이클을 하나의 환경에서 제공하는 것
```

### 핵심 USP (차별화 포인트)
**Visual + Runtime 통합 Agent Control**
- 에이전트를 실행할 수 있고
- 실시간 상태를 볼 수 있고
- 워크플로우와 런타임을 같이 보고
- 실패 원인을 UI에서 디버깅할 수 있는 것

### 지향하는 워크플로우
```
프로젝트 생성 → PM/PL/Dev 팀 구성 → 킥오프
→ LLM이 태스크 자동 생성 → 에이전트 자동 실행
→ 완료 → PM 자동 검토 → 다음 태스크 자동 시작
→ 전체 완료 → 보고서 아카이빙
```

---

## 비전 vs 현실 — 영역별 평가

### 1. Create (생성) — ★★★★☆ 80%

| 비전 | 현실 | Gap |
|------|------|-----|
| 프로젝트 유형 선택 → 최적 워크플로우 자동 구성 | ✅ 10종 카테고리 + 디렉티브 템플릿 | |
| PM/PL/Dev 팀 구성 | ✅ 역할 슬롯 UI + AI 자동 배정 | |
| 킥오프 시 LLM이 태스크 자동 생성 | ✅ 구현 완료 | |
| 태스크가 구체적이고 실행 가능 | ⚠️ 프롬프트 개선 완료했으나 LLM 품질 의존 | LLM이 여전히 모호한 설명 생성 가능 |
| 부족한 정보 시 질문 | ✅ clarification 플로우 | |

**부족한 점:**
- 태스크 생성 후 사용자 확인/편집 단계 없음 — 바로 실행됨
- 프로젝트 템플릿 (boilerplate)에서 자동 생성하는 기능 없음

---

### 2. Run (실행) — ★★★☆☆ 65%

| 비전 | 현실 | Gap |
|------|------|-----|
| 에이전트가 자율적으로 태스크 실행 | ✅ CLI/Runtime 두 모드 지원 | |
| 멀티 에이전트 동시 실행 | ⚠️ Agent Queue로 동시성 관리 | 큐 슬롯 누수 가능, 에이전트 수 제한 |
| 실패 시 자동 재시도 | ❌ **미구현** | 실패한 태스크는 영구 ERR 상태 |
| 태스크 완료 → 다음 태스크 자동 시작 | ⚠️ YOLO 모드에서만 동작 (이번에 추가) | 킥오프 프로젝트에만 적용, TTL 1시간 제한 |
| Git 워크트리 격리 | ⚠️ 실패 시 silent fallback | 사용자 모르게 main에서 직접 작업 |
| 프로세스 관리 | ❌ Windows 좀비 프로세스, graceful shutdown 없음 | 서버 재시작 시 모든 상태 소실 |

**심각한 Gap:**
- **자동 재시도 없음**: 일시적 네트워크 오류로 실패해도 수동 개입 필요
- **PM Oversight 1시간 TTL**: 장시간 프로젝트에서 자동 실행 중단
- **서버 재시작 = 상태 초기화**: 인메모리 상태(pmOversightProjects, enqueuedTaskIds) 전부 소실

---

### 3. Observe (관찰) — ★★★★☆ 85%

| 비전 | 현실 | Gap |
|------|------|-----|
| 실시간 토큰/stdout 스트리밍 | ✅ CLI Window + WebSocket | |
| 태스크 보드 (Kanban/Gantt/DAG) | ✅ 구현 완료 | |
| 에이전트 상태 라이브 뷰 | ✅ Flow Graph + Agent Detail | |
| 비용 추적 | ✅ CLI Cost 위젯 | |
| PM Activity 타임라인 | ⚠️ 구현 완료했으나 보고 메시지 누락 있었음 | 이번에 수정 완료 |
| 알림 시스템 | ⚠️ flood 방지 없음 | 버그 시 알림 폭주 가능 |

**잘 되어 있는 점:**
- macOS UX (Spotlight, Mission Control, Quick Look) — 완성도 높음
- WebSocket 기반 실시간 업데이트 — 대부분 동작

**부족한 점:**
- WebSocket 끊김 시 재동기화 전략 없음
- CLI 출력 배치 큐에서 메시지 유실 가능

---

### 4. Debug (디버깅) — ★★☆☆☆ 40%

| 비전 | 현실 | Gap |
|------|------|-----|
| 실패 원인을 UI에서 디버깅 | ⚠️ 태스크 로그와 CLI 출력만 제공 | 구조화된 에러 분석 없음 |
| 어떤 프롬프트가 에이전트에게 전달됐는지 확인 | ⚠️ `.prompt.txt` 파일로만 확인 | UI에서 프롬프트 조회 불가 |
| 왜 실패했는지 요약 | ❌ exit code만 기록, 원인 분석 없음 | |
| 태스크 재실행/재시도 | ❌ 수동으로만 가능 | 원클릭 재실행 없음 |
| 에이전트 간 충돌 감지 | ❌ **미구현** | 같은 파일 동시 수정 감지 없음 |

**가장 큰 Gap:**
- 시스템이 "OS"를 표방하지만, 디버깅 경험은 로그 파일 수준
- 에이전트가 왜 실패했는지 AI 기반 분석/요약이 없음
- 프롬프트 히스토리 UI 없음 — 개발자가 직접 파일 시스템 탐색 필요

---

### 5. Optimize (최적화) — ★★☆☆☆ 35%

| 비전 | 현실 | Gap |
|------|------|-----|
| 에이전트 성과 분석 | ⚠️ 기본 성과 대시보드 존재 | 심층 분석/추천 없음 |
| 자동 학습 (Rules/Memory/Hooks) | ⚠️ `/learn` 엔드포인트 존재 | 자동 실행 안 됨, 수동 트리거 필요 |
| 프롬프트 최적화 | ❌ **미구현** | A/B 테스트, 프롬프트 버전 관리 없음 |
| 비용 최적화 권장 | ❌ **미구현** | 비용 추적만 하고 절감 제안 없음 |
| 에이전트 역할 재배치 추천 | ❌ **미구현** | 어떤 에이전트가 어떤 태스크에 적합한지 피드백 없음 |

**가장 큰 Gap:**
- "OS"라면 시스템이 점점 나아져야 하는데, 학습 루프가 자동화되지 않음
- 완료된 태스크에서 패턴을 뽑아 다음 프로젝트에 적용하는 흐름 없음

## "Agent OS"에 정말 필요한데 없는 것들 → 해결 현황

### A. 프로세스 관리자 (Process Manager)
- ✅ 프로세스 재시작/복구 — PM이 실패 태스크를 RETRY/REASSIGN 판단
- ✅ 좀비 프로세스 정리 — activeProcesses Map close 이벤트 정리
- ✅ Graceful shutdown — SIGTERM 시 in_progress → planned 복원
- ✅ 상태 영속성 — pm_oversight_state 테이블 + 서버 시작 시 복원

### B. 에러 핸들링 시스템
- ✅ 구조화된 에러 코드 — AI 에러 분석 (8가지 원인 분류)
- ✅ 자동 재시도 — PM LLM이 RETRY 판단 + retry_count 추적
- ✅ 에스컬레이션 — PM LLM이 ESCALATE 판단 → 사용자 알림
- ✅ 에러 통계 — agent_task_fitness 테이블 (성공/실패율)

### C. 자원 관리 (Resource Manager)
- ❌ 토큰 예산 — 프로젝트/태스크별 토큰 한도
- ❌ 동시성 제어 — 파일 락, 브랜치 충돌 방지
- ❌ 디스크/메모리 관리 — worktree 자동 정리, 캐시 관리
- ❌ Rate limit 관리 — API provider별 요청 속도 조절

### D. 학습 시스템 (Learning Loop)
- ✅ 성공/실패 패턴 자동 추출 — PM이 태스크 완료 시 Rules/Memory 자동 추출
- ✅ 에이전트-태스크 적합도 추적 — agent_task_fitness 테이블
- ❌ 프롬프트 버전 관리 — 어떤 프롬프트가 성공률이 높은지 (미구현)
- ✅ 자동 Rules/Memory 생성 — PM auto-learning

## 결론

**AgentDesk는 Phase 21-25를 통해 "에이전트 실행 대시보드"에서 "Agent OS"로 진화했습니다.**

핵심 전환:
- **타이머 폴링 → PM 이벤트 기반 오케스트레이션** (업무 흐름에 setTimeout/setInterval 0건)
- **수동 디버깅 → AI 에러 분석 + 프롬프트 확인 + 원클릭 재실행**
- **일회성 실행 → 자동 학습 + 에이전트 적합도 + 프로젝트 회고**

**남은 핵심 과제**: 자원 관리 (토큰 예산, 동시성 제어)와 플랫폼 확장 (플러그인, 멀티유저).
