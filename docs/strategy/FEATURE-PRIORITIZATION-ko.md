# AgentDesk 기능 우선순위 정리

> 마지막 업데이트: 2026-03-25
> 목적: `docs/FEATURES.md`를 기준으로 현재 기능을 "계속 강화해야 할 핵심 축"과 "정리/축소/후순위화 대상"으로 재분류한다.

---

## 한줄 요약

AgentDesk는 이미 기능 수가 부족한 제품이 아니다. 지금 필요한 것은 더 많은 기능 추가보다, **핵심 운영 루프를 강화하는 기능**과 **복잡성만 키우는 주변 기능**을 분리하는 일이다.

---

## 1. 분류 기준

이번 분류는 다음 기준으로 판단한다.

### 1.1 계속 강화해야 할 기능

아래 조건을 많이 만족할수록 핵심 강화 대상이다.

- AgentDesk의 정체성을 직접 만든다
- 사용자가 반복적으로 가장 자주 쓰는 흐름에 들어간다
- 에이전트 운영/실행/관측/리뷰의 핵심 루프를 강화한다
- 다른 기능의 기반이 된다
- 차별화 포인트로 설명하기 쉽다

### 1.2 정리/축소/후순위화 대상

아래 조건을 많이 만족할수록 정리 대상이다.

- 제품 정체성과 직접 연결되지 않는다
- 사용 빈도 대비 구현/유지 비용이 크다
- 핵심 루프 없이도 독립적으로 존재한다
- 시연 효과는 크지만 실제 반복 가치가 약하다
- 복잡성을 크게 늘리는데 핵심 성과 기여가 낮다

---

## 2. 계속 강화해야 할 핵심 기능

### 2.1 프로젝트 → 태스크 → 실행 → 리뷰 루프

가장 먼저 강화해야 할 축은 다음이다.

- 프로젝트 생성
- 킥오프
- 태스크 생성/배정
- 실행
- PM 리뷰
- 프로젝트 레벨 리뷰

이 루프가 AgentDesk의 가장 핵심적인 제품 경험이다. 이 부분이 강해질수록 AgentDesk는 단순한 AI 실행기가 아니라 "에이전트 운영 시스템"으로 설득력을 가진다.

**관련 기능**

- 프로젝트 시스템
- 태스크 시스템
- 킥오프 파이프라인
- PM 오케스트레이션
- Decision Inbox

### 2.2 에이전트 실행 엔진과 실행 경로 안정화

AgentDesk의 실질 가치는 결국 "에이전트가 실제로 일을 해내는가"에 달려 있다. 따라서 실행 안정성은 모든 상위 기능보다 중요하다.

강화 우선순위는 다음이다.

- CLI/API/runtime 실행 경로 정리
- 에이전트별 동작 일관성 확보
- 실패 재시도/복구/인터럽트 품질 개선
- worktree, dependency, handoff 흐름 안정화

**관련 기능**

- 에이전트 시스템
- 실행 분기
- 인터럽트
- 워크트리
- 서브태스크/핸드오프

### 2.3 관측성과 디버그 경험

AgentDesk가 다른 도구와 차별화되는 가장 강한 포인트 중 하나는 "보인다"는 점이다. 따라서 관측성은 장식이 아니라 핵심 기능이다.

계속 강화해야 할 부분은 다음이다.

- CLI Window
- Task Board
- PM Activity
- Reports
- Dashboard
- WebSocket 이벤트 품질

이 영역은 사용자가 시스템을 신뢰할 수 있게 만드는 핵심이다.

### 2.4 Library 기반 운영 지식 시스템

Skills, Rules, Memory, Hooks는 AgentDesk를 단순 실행기에서 운영 플랫폼으로 끌어올리는 기능이다.

특히 중요한 이유는 다음과 같다.

- 프로젝트마다 다른 규칙을 유지할 수 있다
- 에이전트 운영 경험이 누적된다
- 실행 품질을 반복적으로 높일 수 있다

이 축은 장기적으로 매우 중요하므로 계속 강화 대상이다.

### 2.5 설정, 프로바이더, 로컬 LLM 관리

Settings, API provider, OAuth, CLI 상태, Local LLM은 "운영 가능한 제품"이 되기 위한 기반이다. 매력적인 기능은 아니지만, 실제 사용 지속성과 신뢰성에 직결된다.

이 영역은 flashy하지 않지만 절대 약해지면 안 된다.

### 2.6 메신저 연동 중 핵심 부분

메신저 통합 전체를 다 키우는 것보다는, AgentDesk의 운영 모델과 직접 연결되는 부분을 강화해야 한다.

계속 강화할 대상:

- 태스크 리포트 릴레이
- Direct/Announcement/Directive 흐름
- project_path, 승인, 의사결정 연결

즉 "메신저 자체"보다 "운영 루프와 연결되는 메시징"이 핵심이다.

## 3. 정리/축소/후순위화 대상

### 3.1 Desktop OS 연출 기능의 일부

Desktop, Dock, Mission Control, Wallpaper, App Switcher, Quick Look 같은 기능은 AgentDesk의 개성을 만든다. 하지만 모두가 동일한 비중의 핵심 기능은 아니다.

특히 후순위화 후보는 다음이다.

- Wallpaper
- 과도한 데스크톱 연출 요소
- 자주 쓰이지 않는 전환 효과성 기능

이들은 "있으면 인상적"이지만 핵심 운영 루프를 직접 강화하지는 않는다.

### 3.2 Repo Store

GitHub 트렌딩/클론 중심의 Repo Store는 흥미로운 기능이지만, 현재 AgentDesk의 본질인 멀티에이전트 운영과 직접 연결되는 축은 아니다.

문제는 다음과 같다.

- 제품 메시지를 넓힌다
- 유지비 대비 핵심 루프 기여가 낮다
- 별도 제품처럼 보일 수 있다

따라서 핵심 강화 대상이라기보다 후순위화가 맞다.

### 3.3 Image Studio

Image Studio는 기능적으로 분리된 별도 도메인에 가깝다.

- 텍스트→이미지 생성
- 갤러리
- 인페인팅

이 기능은 AgentDesk의 에이전트 운영 핵심 루프와 직접 연결되지 않는다. 특정 사용 사례에서는 쓸 수 있지만, 지금 단계에서 핵심 강화 대상은 아니다.

### 3.4 Synapse의 넓은 통합 범위

외부 지식 통합 자체는 중요할 수 있지만, Notion/Obsidian/NotebookLM/Figma를 모두 깊게 가져가는 것은 범위가 넓다.

권장 방향은 다음이다.

- 가장 많이 쓰는 1~2개 소스만 강하게 지원
- 나머지는 후순위화

즉, "지식 통합"은 유지하되 "모든 채널 깊게 지원"은 정리 대상이다.

### 3.5 App Runner

App Runner는 재미있고 실용적인 면이 있지만, 성격상 별도 제품처럼 커질 위험이 있다.

특히 다음 점에서 후순위화 후보다.

- 분석
- 설치
- 실행
- 포트 해결

이 흐름은 유용하지만, AgentDesk 핵심 운영 루프보다 별도 도메인에 가깝다. 지금 단계에서는 핵심 강화보다 안정적인 최소 범위 유지가 더 적절하다.

### 3.6 메신저 채널의 폭

Telegram, Discord, Slack, WhatsApp, Google Chat, Signal, iMessage를 모두 깊게 지원하는 것은 운영 비용이 크다.

추천 방향은 다음이다.

- 핵심 1~2개 채널에 집중
- 나머지는 최소 유지

채널 수 확장은 좋은 숫자지만, 품질과 유지비를 빠르게 악화시킬 수 있다.

## 4. 조건부 유지 기능

아래 기능들은 무조건 자르기보다, 조건부로 유지하는 편이 낫다.

### 4.1 Dashboard

Dashboard는 핵심 지표를 보여주는 데 유용하다. 다만 실시간 운영에 꼭 필요한 정보와 보기 좋은 정보가 섞이면 금방 무거워진다.

조건:

- 태스크/에이전트/비용/건강도 중심으로 유지
- 장식성 높은 KPI는 축소

### 4.2 Workflow Builder

워크플로우 빌더는 장기적으로 큰 잠재력이 있다. 하지만 지금 단계에서 너무 넓어지면 핵심 제품보다 별도 플랫폼처럼 커질 수 있다.

조건:

- 핵심 실행 자동화에 직접 연결되는 범위 유지
- 복잡한 composition/확장 기능은 후순위

### 4.3 Local LLM

로컬 LLM은 제품 철학과 잘 맞는다. 다만 백엔드 종류와 모델 관리 범위가 넓어질수록 운영 비용이 커진다.

조건:

- Ollama 중심의 안정적 지원 우선
- 나머지 백엔드는 "지원"보다 "기본 동작 보장" 수준으로 관리

## 6. 전략적 해석

현재 AgentDesk의 문제는 "할 수 있는 기능이 적다"가 아니다. 오히려 "할 수 있는 것이 너무 많아서 중심축이 흐려질 위험"이 더 크다.

따라서 다음 원칙이 필요하다.

1. 핵심 운영 루프에 직접 기여하는 기능을 먼저 강화한다.
2. 개성은 유지하되, 개성이 핵심 루프를 압도하지 않게 한다.
3. 별도 제품처럼 보이는 기능은 확장보다 최소 안정화에 집중한다.
4. 사용자가 가장 자주 밟는 경로를 가장 짧고 강하게 만든다.

---

## 7. 결론

`FEATURES.md` 기준으로 보면 AgentDesk는 이미 충분히 풍부한 시스템이다. 이제 중요한 질문은 "무엇을 더 넣을까"가 아니라 "무엇이 AgentDesk의 본체인가"다.

현재 시점에서 AgentDesk의 본체는 아래다.

- 프로젝트 기반 에이전트 운영
- 태스크 실행과 리뷰
- PM 오케스트레이션
- 실행 관측성과 운영 지식 축적

이 본체를 더 강하게 만드는 기능은 계속 투자해야 한다.  
반대로 본체 없이도 독립적으로 존재하는 기능은 과감히 후순위화하거나 범위를 줄이는 편이 맞다.
