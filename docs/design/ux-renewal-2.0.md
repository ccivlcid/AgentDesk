**버전:** 2.0

## 1. UX 핵심 원칙 — "누구나 쉽게"

모든 화면·컴포넌트 설계 시 이 원칙을 먼저 확인한다.

| 원칙 | 의미 | 적용 예 |
|------|------|---------|
| **평어 우선** | 전문 용어보다 일상 언어를 먼저 쓴다. 불가피한 경우 바로 옆에 설명을 붙인다. | "Gates" → "검토 단계 ⓘ", "Deliverables" → "결과물 ⓘ" |
| **한 번에 하나** | 화면당 사용자가 해야 할 행동은 1개다. | 온보딩: 카테고리 선택 → (다음) → 이름 입력 → (완료) |
| **왜 하는지 설명** | 모든 입력 요청에 한 줄 이유를 제공한다. | "프로젝트 유형을 선택하면 목표·체크포인트·결과물 양식이 자동으로 설정됩니다." |
| **빈 화면은 안내판** | 데이터가 없는 상태를 가장 친절하게 설계한다. | "아직 목표가 없어요. 첫 번째 목표를 추가해볼까요?" + 큰 버튼 |
| **점진적 공개** | 처음에는 단순하게. 사용자가 준비됐을 때 고급 기능을 보여준다. | 카테고리 에디터: 기본 탭만 먼저, "고급 설정 열기"로 나머지 숨김 |
| **실수 방지** | 파괴적 행동 전에는 반드시 확인을 받는다. 되돌릴 수 없는 경우 명시한다. | 삭제 시 "프로젝트와 모든 데이터가 삭제됩니다. 되돌릴 수 없습니다." |
| **상태 항상 표시** | 지금 어디 있는지, 뭘 하고 있는지 항상 보여준다. | 스텝 인디케이터, 저장 중 표시, 성공/실패 토스트 |

## 2. 용어 친화화 가이드

UI에 전문 용어가 나타날 때 반드시 아래 기준을 따른다.

| 내부 개념 | 화면 표시 | 툴팁 (ⓘ 호버) |
|-----------|-----------|--------------|
| Objective | **목표** | 프로젝트가 달성해야 할 큰 방향입니다. 여러 세부 과제로 나눌 수 있어요. |
| Initiative | **세부 과제** | 목표를 이루기 위한 구체적인 행동 단위입니다. |
| Gate | **검토 단계** | 다음 단계로 넘어가기 전에 확인해야 할 체크포인트입니다. |
| Deliverable | **결과물** | 프로젝트가 끝날 때 반드시 만들어야 하는 산출물입니다. |
| KPI | **성과 지표** | 프로젝트 성공을 어떻게 측정할지 정의합니다. |
| Category | **프로젝트 유형** | 같은 유형의 프로젝트에 필요한 목표·지표·결과물 양식을 묶어놓은 템플릿입니다. |
| Risk | **리스크** | 프로젝트 진행을 방해할 수 있는 문제입니다. |
| category_version | (사용자에게 노출 안 함) | — |
| routing_policy | (사용자에게 노출 안 함) | — |

> **규칙**: 내부 DB 필드명(snake_case)은 절대 UI에 노출하지 않는다.

## 3. 변경 범위

| 영역 | As-Is | To-Be |
|------|-------|-------|
| 사이드바 상단 | Company name + CEO name | 로고 + 현재 프로젝트 이름 |
| 1번 메뉴 | Office | **대시보드** |
| 메뉴 순서 | Office→Agents→Library→Dashboard→… | 대시보드→Office→Tasks→Team→Library→… |
| 온보딩 | 직책(CEO/CTO) 선택 | **유형 선택형** 프로젝트 생성 (친절한 안내 포함) |
| 대시보드 | Agent roster + tasks | **4분면**: 목표 / 리스크 / 검토 단계 / 결과물 |
| 프로젝트 없을 때 | 빈 화면 | **환영 온보딩**: 단계별 안내 |
| 설정 | 기존 탭 | 기존 탭 + **프로젝트 유형 관리** (Phase 2) |

## 5. 환영 온보딩 (첫 실행 / 프로젝트 없을 때)

### 5-1. 진입 조건

```
조건: 앱 최초 실행 또는 프로젝트가 0개
진입 화면: 대시보드 영역에 온보딩 화면 표시
(사이드바·헤더는 그대로 유지)
```

### 5-2. 온보딩 Step 1 — 환영 화면

기존 터미널 스타일 `> 첫 번째 프로젝트를 만들어보세요. [OK]` 대신 **사람에게 말을 거는 방식**으로.

```
┌────────────────────────────────────────────────────────────┐
│                                                            │
│              AgentDesk에 오신 걸 환영해요!              │ ← 큰 헤딩 (Sora 700)
│                                                            │
│ AgentDesk는 프로젝트의 목표·리스크·결과물을              │ ← 한 줄 설명
│ 한 곳에서 관리하는 도구입니다.                            │
│                                                            │
│ 시작하려면 첫 번째 프로젝트를 만들어보세요.               │ ← 행동 유도
│                                                            │
│              [프로젝트 만들기 →]                            │ ← Primary 버튼 (크게)
│                                                            │
│         나중에 만들게요 (건너뛰기)                          │ ← Ghost 링크 (작게)
│                                                            │
└────────────────────────────────────────────────────────────┘
```

## 6. 대시보드 2.0 — 4분면 레이아웃

### 6-1. 전체 구조

```
┌─ 헤더 ─────────────────────────────────────────────────────────────────┐
│ 대시보드 / 내 첫 번째 프로젝트 [소프트웨어 개발] [+ 추가] [···] │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────┬───────────────────────────────────────────┐
│                             │                                           │
│ 목표                    │ 리스크                                │
│ 프로젝트가 이루려는 것      │ 주의가 필요한 항목                        │
│                             │                                           │
│ [목표 카드들...]           │ [리스크 카드들...]                        │
│ + 목표 추가하기            │ + 리스크 추가하기                         │
│                             │                                           │
├─────────────────────────────┼───────────────────────────────────────────┤
│                             │                                           │
│ 검토 단계               │ 결과물                                │
│ 완료 전 확인해야 할 것      │ 만들어야 하는 것                          │
│                             │                                           │
│ [검토 단계 목록...]        │ [결과물 목록...]                          │
│ + 검토 단계 추가           │ + 결과물 추가                             │
│                             │                                           │
└─────────────────────────────┴───────────────────────────────────────────┘
```

**핵심 변경점:**
- OBJECTIVES → **목표** + 부제: "프로젝트가 이루려는 것"
- RISKS → **리스크** + 부제: "주의가 필요한 항목"
- GATES → **검토 단계** + 부제: "완료 전 확인해야 할 것"
- DELIVERABLES → **결과물** + 부제: "만들어야 하는 것"

## 11-A. 프로젝트 팀 구성 & 에이전트 배정 UX

### A-1. 기본 개념 (현재 vs 2.0)

```
현재 구조:
 에이전트 → 부서 소속 → 태스크 배정 (프로젝트 개념 없음)

2.0 구조:
 에이전트 → 부서 소속 (유지) + 프로젝트 팀 참여 (추가)
 즉, 에이전트는 전역 풀에 있고, 프로젝트마다 팀원을 초대해서 구성
```

에이전트를 "배정한다"는 개념이 아니라 **"팀을 꾸린다"** 는 프레임으로 설계.

---

### A-2. 전체 흐름 (3가지 진입점)

```
진입점 1: 프로젝트 생성 완료 직후
 "프로젝트가 만들어졌어요! 이제 함께 일할 팀원을 추가해볼까요?"
 [팀원 추가하기] / [나중에 추가할게요]

진입점 2: 대시보드 → 팀 섹션 → [+ 팀원 추가]
 (언제든 팀 구성 변경 가능)

진입점 3: 태스크 생성 시 담당자 선택
 "아직 이 프로젝트에 팀원이 없어요. 지금 추가할까요?"
 → 팀원 추가 모달로 연결
```

---

### A-3. 프로젝트 생성 직후 — 팀원 초대 유도

```
┌────────────────────────────────────────────────────────────────┐
│                                                                │
│    "쇼핑몰 앱 개발 2026" 프로젝트가 만들어졌어요!            │ ← 성공 메시지
│                                                                │
│ 이제 함께 일할 팀원을 추가해볼까요?                          │ ← 다음 행동 유도
│ 팀원에게 태스크를 배정하고 진행 상황을 볼 수 있어요.          │ ← 왜 하는지 설명

## 11-B. 페르소나 에이전트 UX — "누구나 쉽게"

> **전제 문서:** [strategy/agent-persona-system.md](../strategy/agent-persona-system.md) — 시스템 아키텍처·프롬프트·구현 계획은 이 문서를 따른다.
> 이 섹션은 **2.0 "누구나 쉽게" 관점의 UX 스펙만** 다룬다.

### B-1. 핵심 UX 문제

페르소나 시스템은 AgentDesk의 독창적 차별점이지만,
**"Linus Torvalds가 누구인지 모르는 사람"** 도 이 기능을 써야 한다.

| 현재 설계 | 문제 | 개선 |
|-----------|------|------|
| 인물 이름 + `[TECH]` 카테고리 태그 중심 | 인물을 모르면 선택 불가 | **"일하는 방식"을 먼저, 이름은 부제** |
| "1st Principles", "Day 1" 같은 영어 숙어 | 일반 사용자에게 낯설음 | 쉬운 한국어 한 줄 설명 |
| 카탈로그를 처음부터 직접 탐색 | 어떤 페르소나가 맞는지 모름 | 역할/부서에 따른 **자동 추천** |
| `[JOBS]` 배지만 표시됨 | 맥락 없음 | hover 시 "Jobs 스타일: 단순함·사용자 경험" |

 단순함 추구, 사용자 경험 우선,
 제품 기획·UX 검토에 최적."
```

배지 표시 원칙:
- 공간 있을 때: `단순함·사용자 경험 스타일` (방식명)
- 공간 좁을 때: `[Jobs 스타일]` (이름 + "스타일" 접미사)
- 아이콘만: `` (최소 공간)

### B-7. 처음 페르소나를 접하는 사용자 — 안내 패턴

```
┌──────────────────────────────────────────────────────────────┐
│ 이 팀원에게 사고 방식을 설정할 수 있어요.                │
│     어떻게 생각하고 일하는지 스타일을 정하면                 │
│     같은 일도 다른 관점으로 처리해요.          [설정하기]    │
└──────────────────────────────────────────────────────────────┘

조건: 에이전트에 persona_id 없음 + 팀원 상세 첫 방문
배경: rgba(245,158,11,0.05), border: 1px solid rgba(245,158,11,0.2)
[설정하기]: 페르소나 카탈로그 모달 오픈
```
