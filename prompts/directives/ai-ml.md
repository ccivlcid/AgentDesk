## 기술스택
- 언어: (예: Python, R, Julia 등)
- ML 프레임워크: (예: PyTorch, TensorFlow, scikit-learn, HuggingFace 등)
- 데이터: (예: Pandas, Polars, DuckDB, Spark 등)
- 실험 추적: (예: MLflow, Weights & Biases, Neptune 등)
- 서빙: (예: FastAPI, TorchServe, vLLM 등)

## 목표
**재현 가능하고 설명 가능한** AI/ML 파이프라인을 구축한다.
데이터 수집부터 모델 서빙까지 전 과정이 자동화되고, 모든 실험이 추적 가능해야 한다.

## 작업 원칙
- **재현 가능성이 절대 최우선**이다. 코드, 데이터, 환경, 하이퍼파라미터 모두 버전 관리. 같은 코드 + 같은 데이터 = 같은 결과.
- 모든 실험에 하이퍼파라미터, 데이터 버전, 결과 메트릭, 학습 시간을 기록한다.
- 랜덤 시드를 고정한다(`seed=42`). 시드 없이 실행한 결과는 신뢰하지 않는다.
- 노트북(Jupyter)은 탐색/시각화 전용. 프로덕션 파이프라인은 `.py` 스크립트로 변환.
- 데이터 품질 검증(null 비율, 분포 이상, 중복, 라벨 불균형)을 학습 전에 반드시 수행한다.
- **베이스라인 없이 복잡한 모델부터 시작하지 않는다.**

## 태스크 분해
- 각 단계의 입력/출력을 파일(parquet, csv, onnx 등)로 명확히 분리:
  1. 데이터 수집/정제 (raw → cleaned)
  2. EDA + 데이터 검증 (분포, 이상치, 라벨 품질)
  3. 베이스라인 모델 (가장 단순한 모델로 성능 하한선 확립)
  4. 실험 루프: 가설 → 실험 → 결과 기록 → 다음 가설. 한 번에 하나의 변수만 변경.
  5. 평가/비교 (베이스라인 대비, 통계적 유의성 확인)
  6. 서빙/배포 (모델 패키징, API, 모니터링)

## 품질 기준
- 데이터 품질 검증 통과 후에만 학습 시작.
- 평가 지표가 베이스라인을 **통계적으로 유의미하게** 넘을 때만 배포.
- 실험 로그 필수: 하이퍼파라미터, 데이터 버전, train/val/test 메트릭, 학습 시간.
- **데이터 누수(data leakage) 점검**: train/test split은 전처리 전에 수행.
- 모델 카드 작성: 용도, 한계, 알려진 편향, 성능 지표, 학습 데이터 설명.

## 리뷰
- 코드 리뷰보다 **실험 설계 리뷰**가 더 중요하다:
  - 가설을 공정하게 검증하는가? 베이스라인이 적절한가?
  - 데이터 누수, 과적합 징후는 없는가?
  - 평가 지표가 비즈니스 목표와 일치하는가?
- 서빙 리뷰: 지연시간, 메모리 사용량, 롤백 전략.

## 우선순위
```
재현성 ≫ 정확도 > 설명 가능성 > 속도
```
- "화려한 최신 모델"보다 "검증된 베이스라인 + 점진적 개선".
