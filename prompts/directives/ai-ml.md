## 기술스택
- 언어: (예: Python, R, Julia 등)
- ML 프레임워크: (예: PyTorch, TensorFlow, scikit-learn, HuggingFace 등)
- 데이터: (예: Pandas, Polars, DuckDB, Spark 등)
- 실험 추적: (예: MLflow, Weights & Biases, Neptune 등)
- 서빙: (예: FastAPI, TorchServe, Triton, vLLM 등)
- 오케스트레이션: (예: Airflow, Prefect, Dagster 등)

## 목표
**재현 가능하고 설명 가능한** AI/ML 파이프라인을 구축한다.
데이터 수집부터 모델 서빙까지 전 과정이 자동화되고, 모든 실험이 추적 가능해야 한다.

## 작업 원칙
- **재현 가능성이 절대 최우선**이다. 코드, 데이터, 환경, 하이퍼파라미터가 모두 버전 관리되어야 한다. 같은 코드 + 같은 데이터 = 같은 결과.
- 모든 실험에 하이퍼파라미터, 데이터 버전, 결과 메트릭, 학습 시간, GPU 사용량을 기록한다.
- 랜덤 시드를 고정한다 (`seed=42` 등). 시드 없이 실행한 결과는 신뢰하지 않는다.
- 노트북(Jupyter)은 탐색(EDA)과 시각화 전용이다. 프로덕션 파이프라인은 반드시 `.py` 스크립트로 변환한다.
- 데이터 전처리는 **멱등성**을 보장한다. 같은 원본 데이터에 같은 전처리를 돌리면 항상 같은 결과.
- GPU 메모리를 의식한다. batch size, gradient accumulation, mixed precision(fp16/bf16), gradient checkpointing을 적절히 활용한다.
- 데이터 품질 검증(validation)을 학습 전에 반드시 수행한다: null 비율, 분포 이상, 중복, 라벨 불균형, 포맷 일관성.
- 모델 크기와 추론 지연시간의 트레이드오프를 항상 고려한다. 정확도 0.1% 올리려고 모델을 10배 키우지 않는다.

## 태스크 분해
- **파이프라인 단계별로 독립 실행 가능**하게 구성한다. 각 단계의 입력/출력은 파일(parquet, csv, pickle, onnx 등)로 명확히 분리.
  1. **데이터 수집/정제**: raw → cleaned 데이터. 데이터 소스와 버전을 기록.
  2. **EDA + 데이터 검증**: 분포 확인, 이상치 탐지, 라벨 품질 검증. 시각화 포함.
  3. **베이스라인 모델**: 가장 단순한 모델(로지스틱 회귀, 랜덤 포레스트 등)로 성능 하한선 확립.
  4. **실험 루프(반복)**: 가설 → 실험 설계 → 실행 → 결과 기록 → 다음 가설. 한 번에 하나의 변수만 바꾼다.
  5. **평가/비교**: 베이스라인 대비 성능 비교. 통계적 유의성 확인.
  6. **서빙/배포**: 모델 패키징, API 서빙, 모니터링(데이터 드리프트, 성능 저하 감지).
- **베이스라인 없이 복잡한 모델부터 시작하지 않는다.** 베이스라인이 없으면 개선의 기준이 없다.
- 실험은 한 번에 하나의 변수(모델 구조, 하이퍼파라미터, 데이터 전처리 방식 등)만 변경한다.

## 품질 기준
- 데이터 품질 검증 통과 후에만 학습을 시작한다. 검증 실패 시 데이터 정제부터 다시.
- 평가 지표가 베이스라인을 **통계적으로 유의미하게** 넘을 때만 배포한다. 1회 실행 결과만으로 판단하지 않는다.
- 실험 로그 필수 항목: 하이퍼파라미터, 데이터 버전, train/val/test 메트릭, 학습 시간, 모델 크기.
- **데이터 누수(data leakage) 점검**: train/test split은 전처리 전에 수행. 미래 데이터가 학습에 포함되지 않는지 확인.
- 모델 카드(Model Card) 작성: 용도, 한계, 알려진 편향, 성능 지표, 학습 데이터 설명.
- 프로덕션 서빙 시: P95 추론 지연시간 목표 설정, 메모리 사용량 상한, 동시 요청 처리 테스트.

## 리뷰
- 코드 리뷰보다 **실험 설계 리뷰**가 더 중요하다. 리뷰 관점:
  - 이 실험 설계가 가설을 공정하게 검증하는가?
  - 비교 대상(베이스라인)이 적절한가?
  - 데이터 누수, 라벨 누출, 과적합 징후는 없는가?
  - 평가 지표가 비즈니스 목표와 일치하는가?
- 프로덕션 서빙 리뷰: 지연시간, 메모리 사용량, 에러 핸들링, 모델 버전 관리, 롤백 전략.
- 데이터 파이프라인 리뷰: 원본 데이터 변경 시 파이프라인이 정상 동작하는가? 실패 시 알림이 가는가?

## 우선순위
```
재현성 ≫ 정확도 > 설명 가능성 > 속도
```
- 블랙박스 금지. 결과를 설명할 수 없으면 배포하지 않는다.
- "화려한 최신 모델"보다 "검증된 베이스라인 + 점진적 개선".
- 정확도 0.5% 올리는 복잡한 앙상블보다, 재현 가능하고 유지보수 가능한 단일 모델이 낫다.
