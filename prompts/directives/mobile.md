## 기술스택
- 프레임워크: (예: React Native, Flutter, Swift, Kotlin 등)
- 상태관리: (예: Zustand, Redux, Riverpod 등)
- 네비게이션: (예: React Navigation, Go Router 등)
- 백엔드: (예: Firebase, Supabase, 자체 API 등)
- CI/CD: (예: Fastlane, Bitrise, Codemagic 등)

## 목표
iOS/Android 사용자에게 **네이티브에 준하는 매끄러운 경험**을 제공하는 모바일 앱을 구축한다.
터치 인터랙션, 오프라인 대응, 플랫폼 가이드라인 준수를 핵심으로 한다.

## 작업 원칙
- **터치 UX가 최우선**이다. 모든 인터랙션은 즉각 반응해야 한다.
- 네트워크 불안정/오프라인을 항상 가정한다. optimistic UI + 로컬 캐시 기본 적용.
- 60fps 유지. 무거운 연산은 반드시 메인 스레드 밖에서 처리한다.
- Apple HIG / Material Design 3 가이드라인을 준수한다.
- 딥링크, 푸시 알림, 권한 요청 플로우를 초기 설계에 포함한다.
- 다크 모드 기본 지원. 접근성(VoiceOver/TalkBack)을 고려한다.

## 태스크 분해
- **화면(Screen) 단위**: 한 태스크 = 한 화면 완성(UI + 로직 + API 연동).
- 순서:
  1. 네비게이션 스켈레톤: 모든 화면 빈 껍데기 + 라우팅 + 탭/드로어 구조
  2. 공통 컴포넌트: 버튼, 입력 필드, 카드, 바텀시트, 토스트, 로딩 인디케이터
  3. 개별 화면 구현 (병렬 가능)
  4. 화면 간 데이터 흐름 통합: 딥링크 테스트, 전역 상태 동기화
- 애니메이션/전환 효과는 기능 구현 후 별도 태스크로 다듬는다.

## 품질 기준
- 모든 터치 타겟 최소 **44×44pt** (iOS) / **48×48dp** (Android).
- 리스트는 가상화(FlatList, FlashList, LazyColumn 등) 기본 적용.
- 앱 콜드 스타트 **3초 이내**.
- 에러 상태(네트워크 끊김, 서버 500, 빈 데이터)에 대한 UI 필수. 빈 화면 금지.
- 화면 이탈 시 구독, 타이머, 이벤트 리스너 정리 확인.

## 리뷰
- **design 에이전트** 리뷰 관점: 시각적 일관성, 터치 영역, 에러/빈 상태 처리.
- 성능 프로파일링: 스크롤 프레임 드롭, 앱 시작 시간, 메모리 사용량.
- 플랫폼별(iOS/Android) 동작 차이 확인.

## 우선순위
```
UX > 성능 > 안정성 > 기능 수
```
- "3개 화면이 완벽하게" > "10개 화면이 어설프게".
