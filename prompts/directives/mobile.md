- 프레임워크: (예: React Native, Flutter, Swift, Kotlin 등)
- 상태관리: (예: Zustand, Redux, Riverpod, MobX 등)

## 목표
iOS/Android 사용자에게 **네이티브에 준하는 매끄러운 경험**을 제공하는 모바일 앱을 구축한다.
터치 인터랙션, 오프라인 대응, 플랫폼 가이드라인 준수를 핵심으로 한다.

## 작업 원칙
- **터치 UX가 최우선**이다. 모든 인터랙션은 즉각 반응해야 하고, 지연이 느껴지면 실패다.
- 네트워크 불안정/오프라인 상황을 항상 가정한다. optimistic UI + 로컬 캐시 패턴을 기본으로 적용한다.
- 60fps 유지를 목표로 한다. 무거운 연산(이미지 처리, 정렬, 검색)은 반드시 메인 스레드 밖에서 처리한다.
- Apple HIG(Human Interface Guidelines) / Material Design 3 가이드라인을 준수한다. 플랫폼별 패턴(뒤로가기, 스와이프 제스처, 바텀시트 등)을 따른다.
- 딥링크, 푸시 알림, 권한 요청(카메라, 위치, 알림 등) 플로우를 초기 설계에 포함한다. 나중에 끼워넣으면 구조가 꼬인다.
- 앱 크기(bundle size)를 의식한다. 불필요한 네이티브 모듈/폰트/이미지 추가를 자제한다.
- 다크 모드를 기본 지원한다. 시스템 설정 연동 + 앱 내 수동 전환.
- 접근성(VoiceOver/TalkBack)을 고려한다. 모든 터치 요소에 accessibilityLabel을 부여한다.

## 태스크 분해
- **화면(Screen) 단위**로 쪼갠다. 한 태스크 = 한 화면 완성(UI + 로직 + API 연동).
- 순서:
  1. **네비게이션 스켈레톤**: 모든 화면 빈 껍데기 + 라우팅 + 탭/드로어 구조
  2. **공통 컴포넌트**: 버튼, 입력 필드, 카드, 바텀시트, 토스트, 로딩 인디케이터
  3. **개별 화면 구현** (병렬 가능): 각 화면의 UI + 상태 + API 연동
  4. **화면 간 데이터 흐름 통합**: 네비게이션 파라미터, 전역 상태 동기화, 딥링크 테스트
- API 연동은 화면 구현과 함께 진행한다. 목(mock) 데이터로 시작해서 실제 API로 교체하는 방식.
- 애니메이션/전환 효과는 기능 구현 후 별도 태스크로 다듬는다.

## 품질 기준
- 모든 터치 타겟 최소 **44×44pt** (iOS) / **48×48dp** (Android). 이보다 작으면 무조건 수정.
- 리스트는 가상화(FlatList, FlashList, RecyclerView, LazyColumn) 기본 적용. 100개 이상 아이템에서 스크롤 프레임 드롭 없어야 한다.
- 키보드가 올라올 때 입력 필드가 가려지지 않아야 한다. KeyboardAvoidingView 또는 동등한 처리 필수.
- 앱 콜드 스타트 **3초 이내**. 스플래시 스크린으로 가리는 것은 해결이 아니다.
- 메모리 누수 없음. 화면 이탈 시 구독, 타이머, 이벤트 리스너 정리 확인.
- 에러 상태(네트워크 끊김, 서버 500, 빈 데이터)에 대한 UI가 있어야 한다. 빈 화면 금지.
- 이미지 로딩에 플레이스홀더/스켈레톤을 사용한다. 이미지 팝인 금지.

## 리뷰
- **design 에이전트**가 모든 UI 태스크를 리뷰한다.
- 리뷰 관점:
  - 시각적 일관성: 디자인 시스템을 따르고 있는가?
  - 터치 영역: 모든 버튼/링크가 충분히 큰가?
  - 애니메이션: 자연스럽고 목적이 있는가? (장식용 애니메이션 금지)
  - 에러/빈 상태: 유저가 막히는 화면이 없는가?
- 성능 프로파일링 리뷰: 스크롤 프레임 드롭, 앱 시작 시간, 메모리 사용량.
- 플랫폼별(iOS/Android) 동작 차이 확인. 특히 뒤로가기 제스처, 상태바 처리, 노치 대응.

## 우선순위
```
UX > 성능 > 안정성 > 기능 수
```
- 적은 기능이라도 매끄럽게. "3개 화면이 완벽하게" > "10개 화면이 어설프게".
- 기능을 추가하기 전에 기존 화면의 완성도를 먼저 올린다.
