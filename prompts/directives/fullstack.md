## 기술스택
- 프론트엔드: (예: React, Vue, Svelte 등)
- 백엔드: (예: Node.js/Express, Django, Spring 등)
- DB: (예: PostgreSQL, MySQL, MongoDB 등)
- 인프라: (예: Docker, AWS, Vercel 등)
- 패키지 매니저: (예: pnpm, npm, yarn 등)

## 목표
프론트엔드 + 백엔드 + DB + 인증을 포함하는 **프로덕션 수준의 풀스택 애플리케이션**을 구축한다.
실제 사용자에게 배포할 수 있는 완성도를 목표로 하며, 유지보수와 확장을 염두에 둔 아키텍처를 설계한다.

## 작업 원칙
- 에러 핸들링, 로깅, 입력 검증은 필수다.
- **API 계약(스키마)을 먼저 확정**한 후 프론트/백을 병렬 구현한다. 계약 없이 UI 구현 시작 금지.
- DB 스키마 변경은 반드시 마이그레이션 파일로 관리한다.
- 시크릿(API 키, DB 비밀번호)은 코드에 절대 하드코딩하지 않는다. 환경 변수 사용.
- 모든 사용자 입력은 서버 측에서 검증한다.
- DRY 원칙을 따르되, **3번 이상 반복**될 때만 추상화한다.

## 태스크 분해
- **레이어별 분리**:
  1. DB 스키마 설계 + 마이그레이션
  2. API 엔드포인트 (인증/인가 포함)
  3. 비즈니스 로직 (서비스 레이어)
  4. UI 컴포넌트 + 페이지
  5. 통합 테스트 + E2E 테스트
- 인증/인가 레이어를 초반에 구축한다. 모든 후속 기능의 전제조건.
- 독립된 API 엔드포인트, 서로 무관한 UI 페이지는 병렬 진행한다.

## 품질 기준
- 비즈니스 로직 단위 테스트 필수. 커버리지 목표 70% 이상.
- API에 일관된 에러 응답 포맷과 적절한 HTTP 상태 코드 필수.
- N+1 쿼리 금지. 민감 데이터는 로그에 절대 출력하지 않는다.
- DB 마이그레이션은 롤백 가능하게 작성한다(up + down).

## 리뷰
- 3라운드:
  - **dev**: 기능 정확성, 코드 품질, 아키텍처 일관성
  - **qa**: 안정성, 엣지케이스, 에러 시나리오
  - **devsecops**: 보안, 인증/인가 누락, 인프라 설정
- DB 스키마 변경, 인증 로직 변경, API 계약 변경은 전원 리뷰.
